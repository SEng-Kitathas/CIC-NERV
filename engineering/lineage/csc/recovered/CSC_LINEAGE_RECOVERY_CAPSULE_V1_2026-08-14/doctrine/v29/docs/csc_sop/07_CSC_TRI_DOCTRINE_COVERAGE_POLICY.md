# 07 — CSC TRI-DOCTRINE COVERAGE POLICY

## Purpose
This document defines how CSC measures 1:1 coverage against the tri-doctrine stack.

Coverage does not mean every sentence becomes a regex.
Coverage means every load-bearing requirement class has an inspectable enforcement surface or an explicit gap marker.

## Coverage statuses
- `enforced` — CSC has an active check/report/guard for the requirement class
- `partial` — CSC has some pressure but not yet promotion-grade enforcement
- `missing` — CSC lacks a real enforcement surface

## Required doctrine coverage classes
CSC SHALL track at least these classes:
- authority_and_mode_control
- evidence_before_inference
- cross_domain_grounding
- theoretical_maximum_pressure
- holonic_clarity
- cognitive_conservation_and_idiom
- typed_surface_and_boundary_integrity
- specimen_governance_separation
- anti_pattern_residue
- verification_ladder_and_non_llm_anchors
- promotion_discipline
- continuity_shadow_pair
- rehydration_and_restart_discipline
- append_only_and_mutation_honesty
- archive_integrity_and_chain_trust
- experiment_pressure_and_reporting
- lifecycle_retention_and_probe_protection
- substrate_sovereignty_and_dependency_pressure
- sop_freshness_and_mutation_lag

## Coverage rule
Every active CSC pass SHALL emit a doctrine coverage report showing:
- requirement id
- doctrine classes involved
- authority layers involved
- current status
- enforcement surfaces present
- active blockers or gaps

## Promotion rule
CSC SHALL NOT call itself canon-clean if any load-bearing doctrine class is `missing`.
A `partial` class is allowed only if the gap is explicit and the remaining coverage still honestly bounds the claim.

## Hazard
False 1:1 claims are worse than incomplete coverage.
If a doctrine class is only loosely pressured, mark it `partial` and say why.
