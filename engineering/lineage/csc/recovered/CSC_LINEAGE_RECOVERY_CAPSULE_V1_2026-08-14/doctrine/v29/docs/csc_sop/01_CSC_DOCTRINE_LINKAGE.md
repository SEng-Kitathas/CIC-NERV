# 01 — CSC DOCTRINE LINKAGE

## Purpose
This document makes the CSC standard **1:1 linked** to the active code doctrine and archive control spine.

CSC SHALL NOT drift into an independent style religion.
It exists to embody the doctrine already governing the lab.

## Doctrine Links
### From UNIFIED CODE STANDARDS DOCTRINE
CSC SHALL enforce or pressure the following:
- PDVER lifecycle
- Holonic architecture questions
- Failure locality
- typed boundaries
- anti-pattern removal
- promotion discipline
- specimen/governance separation
- no dict-smear across boundaries unless absolutely required

### From CODEX OMEGA
CSC SHALL pressure:
- theoretical-maximum quality direction
- substrate sovereignty
- cognitive alignment
- verification over narrative confidence
- anti-naive implementation shape

### From the PCMMAD archive
CSC SHALL remain subordinate to:
- ingress boundary law
- build/discussion mode discipline
- Live Shadow / Design Thread Stream continuity pair
- rescue / post-processing layer
- promotion + demotion rules
- recursive replay when interpretation changes

## 1:1 Mapping Surface
Every CSC check SHOULD map to one of these doctrine classes:
- `boundary_integrity`
- `typed_surface_integrity`
- `anti_pattern_residue`
- `holonic_clarity`
- `promotion_integrity`
- `continuity_surface_integrity`
- `verification_surface_integrity`
- `machine_specific_brittleness`

Checks that do not map cleanly to doctrine SHALL be treated as suspect until justified.

## Required CSC Artifacts
CSC SHOULD be able to emit or refresh these artifact classes:
- whole-lab cleanup report
- holonic audit report
- anti-pattern inversion report
- lifecycle / promotion pressure report
- SOP availability report
- self-audit report

## Invariant
CSC SHALL be stricter about false authority than false polish.
A clean-looking report with doctrine drift is worse than an ugly report with truthful pressure.

## Hazard
The primary hazard is **cleanup monoculture**:
- optimizing for regex hits instead of architecture truth
- deleting granularity needed for macro synthesis
- treating style compliance as equivalent to verification
- treating one doctrine phrase as sufficient authority without archive consensus
