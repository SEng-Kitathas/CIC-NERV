# 08 — CSC IDIOMATIC EXPRESSION SOP

## Purpose
This SOP makes CSC explicitly responsible for code style and idiomatic expression in the sense required by the tri-doctrine stack.

This is not fashion policing.
It is doctrine-backed pressure for code that is easier to reason about, less naive, and more faithful to its invariant.

## What CSC SHOULD inspect
- parameter count against cognitive conservation
- nesting depth against local reasoning limits
- overly long functions that exceed one coherent job
- silent exception handling / swallowed failure
- misleading wrapper layers or unnecessary indirection
- compatibility shims that outlive their purpose
- naming that obscures domain truth
- transitional structures that should now be typed holons

## Output expectation
For each significant idiom/style finding, CSC SHOULD emit:
- file
- current anti-pattern or awkward expression
- why it harms reasoning or truthfulness
- target invariant
- cleaner primitive or idiomatic expression
- doctrine linkage

## Non-negotiable
CSC style pressure SHALL remain subordinate to truth and verification.
A prettier but less truthful structure is a regression.

## Hazard
Generic linter-fashion that is not tied back to tri-doctrine law is not authoritative here.
