# V29 release verification contract

A release is promotable only when the final embodied tree satisfies all required anchors:

- complete source-corpus inventory and decision ledger
- Python compile verification over runtime, tests, tools, and system
- complete regression suite
- baseline self-test with at least 49 routes and 87 tools
- schema authority with exactly 30 unique operation IDs
- protocol runtime contract tests, including tamper detection, proportionate rigor, evidence freshness, sealed identity, waivers, and mode enforcement
- semantic footgun/dataflow gate
- full-route trace with 49/49 coverage and no unexpected 5xx
- negative-contract trace
- stateful replay/idempotency trace
- concurrency trace
- security-boundary trace
- browser-sidecar resilience trace
- live-parity trace
- package-integrity gate
- launcher-script audit
- CSC doctrine availability, freshness, holonic audit, doctrine coverage, and PDVER cycle
- final manifest verification after fresh ZIP extraction

A green process exit is insufficient when the claimed sub-invariant is false. Reports expose sub-results and derive aggregate clean state from those results.

Windows PowerShell parsing, actual ngrok tunneling, live D:/E: mounts, and a real Custom GPT callback remain host-bound verification and must be completed before machine promotion.
